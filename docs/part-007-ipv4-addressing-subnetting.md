## Step 61 — ทวนความจำ Binary / Decimal / Hex Conversion + Powers of 2

Subnetting ทั้งหมดคือการเล่นกับ**เลขฐาน 2 (Binary)** ที่ถูกเขียนแสดงผลเป็นเลขฐาน 10 (Decimal)
ให้มนุษย์อ่านง่าย ส่วนเลขฐาน 16 (Hexadecimal) จะสำคัญมากขึ้นเมื่อเข้า IPv6 ใน **Part 8**
และใช้กับ MAC Address (เรียนแล้วใน Part 1) — ก่อนไปคำนวณ subnet ต้องทวนพื้นฐาน 3 ฐานเลขนี้ให้แม่นก่อน

### Powers of 2 (2^1 – 2^8) — ต้องจำให้ขึ้นใจ เพราะใช้คำนวณจำนวน subnet/host ตลอดหลักสูตร

| Exponent | ค่า | ใช้ทำอะไรในการ Subnet |
|---|---|---|
| 2^1 | 2 | จำนวน subnet เมื่อยืม (borrow) 1 bit / จำนวน host ที่ /30 (2 usable) |
| 2^2 | 4 | จำนวน subnet เมื่อยืม 2 bit |
| 2^3 | 8 | จำนวน subnet เมื่อยืม 3 bit |
| 2^4 | 16 | จำนวน subnet เมื่อยืม 4 bit / จำนวน host ที่ /28 |
| 2^5 | 32 | จำนวน subnet เมื่อยืม 5 bit / จำนวน host ที่ /27 |
| 2^6 | 64 | จำนวน subnet เมื่อยืม 6 bit / จำนวน host ที่ /26 |
| 2^7 | 128 | จำนวน subnet เมื่อยืม 7 bit / จำนวน host ที่ /25 |
| 2^8 | 256 | จำนวน subnet เมื่อยืม 8 bit (1 octet เต็ม) / จำนวน host ที่ /24 |

> **สูตรที่ต้องจำ**: จำนวน subnet ที่ได้ = 2^(จำนวน bit ที่ยืมมาจาก host part)
> จำนวน host ที่ใช้ได้จริง (usable) = 2^(จำนวน host bit ที่เหลือ) − 2 (หัก Network Address และ
> Broadcast Address ออก — ยกเว้น /31 ที่ใช้ทั้ง 2 address เป็น point-to-point ตาม RFC 3021)

### ค่า Byte แต่ละตำแหน่ง (Bit Value) — พื้นฐานการแปลง Binary ↔ Decimal

หนึ่ง Octet (8 bit) มีค่าตำแหน่งดังนี้ (ซ้ายไปขวา = bit สูงไปต่ำ):

| Bit position | 7 | 6 | 5 | 4 | 3 | 2 | 1 | 0 |
|---|---|---|---|---|---|---|---|---|
| ค่า (2^n) | 128 | 64 | 32 | 16 | 8 | 4 | 2 | 1 |

### ตาราง Magic Number (ค่า Octet ที่ใช้ทำ Subnet Mask บ่อยที่สุด) — Decimal / Binary / Hex

| Decimal | Binary | Hex |
|---|---|---|
| 0 | 00000000 | 0x00 |
| 128 | 10000000 | 0x80 |
| 192 | 11000000 | 0xC0 |
| 224 | 11100000 | 0xE0 |
| 240 | 11110000 | 0xF0 |
| 248 | 11111000 | 0xF8 |
| 252 | 11111100 | 0xFC |
| 254 | 11111110 | 0xFE |
| 255 | 11111111 | 0xFF |

ตารางนี้คือ **"ค่า Magic Number"** — ทุกค่าที่เป็นไปได้ของ Octet ใน Subnet Mask มีแค่ 9 ค่านี้เท่านั้น
(0, 128, 192, 224, 240, 248, 252, 254, 255) เพราะ Subnet Mask ต้องเป็น bit 1 ต่อกันจากซ้ายเสมอ
ไม่มีทางเป็น `10100000` (1 สลับ 0) ได้ — จำ 9 ค่านี้ให้ขึ้นใจ จะช่วยคำนวณ subnet ได้เร็วมาก

### Worked Example 1 — แปลง Decimal → Binary

**แปลง 172 เป็น Binary:**
```
172 = 128 + 32 + 8 + 4
    =  1  +  0 + 1 + 0 + 1 + 0 + 0 + 1   (ตำแหน่ง 128 64 32 16 8 4 2 1)
172 (decimal) = 10101100 (binary)
```
ตรวจสอบ: 128+32+8+4 = 160+8+4 = 172 ✅

### Worked Example 2 — แปลง Binary → Decimal

**แปลง 11001011 เป็น Decimal:**
```
bit:    1   1   0   0   1   0   1   1
ค่า:   128  64  32  16   8   4   2   1
รวม = 128+64+8+2+1 = 203
11001011 (binary) = 203 (decimal)
```

### Worked Example 3 — แปลง Decimal → Hexadecimal (สำคัญสำหรับ IPv6 ใน Part 8)

**แปลง 205 เป็น Hex:** หารด้วย 16 → 205 ÷ 16 = 12 เศษ 13 → 12 = `C`, 13 = `D` (ในเลขฐาน 16 ใช้ A-F แทน 10-15)
```
205 (decimal) = CD (hex) = 11001101 (binary)
```

**แปลง 0xA3 กลับเป็น Decimal:** A = 10, 3 = 3 → (10 × 16) + 3 = 163
```
0xA3 (hex) = 163 (decimal) = 10100011 (binary)
```

### ตารางเทียบ Decimal ↔ Binary ↔ Hex ของค่าที่พบบ่อยใน Lab (IP Address จริง)

| Decimal | Binary | Hex |
|---|---|---|
| 10 | 00001010 | 0x0A |
| 16 | 00010000 | 0x10 |
| 20 | 00010100 | 0x14 |
| 30 | 00011110 | 0x1E |
| 40 | 00101000 | 0x28 |
| 99 | 01100011 | 0x63 |
| 168 | 10101000 | 0xA8 |
| 172 | 10101100 | 0xAC |
| 192 | 11000000 | 0xC0 |
| 203 | 11001011 | 0xCB |
| 255 | 11111111 | 0xFF |

> **ทำไมต้องรู้ Hex ด้วย?** Hex ใช้แสดง MAC Address (Part 1) และเป็นฐานหลักของ **IPv6 Address**
> ทั้งหมด (Part 8) — การแม่น Binary/Hex ตั้งแต่ Part นี้จะทำให้ Part 8 เรียนง่ายขึ้นมาก

## Step 62 — Subnet Mask พื้นฐาน และ Magic Number / Block Size Method

### Subnet Mask ทำงานอย่างไรในระดับ Bit

Subnet Mask คือเลข 32-bit ที่บอกว่า bit ไหนของ IP Address เป็น **Network portion** (bit ที่เป็น 1)
และ bit ไหนเป็น **Host portion** (bit ที่เป็น 0) เมื่อนำ IP Address มาทำ **Bitwise AND** กับ Subnet Mask
จะได้ **Network Address**

```
IP Address:     192.168.10.130  = 11000000.10101000.00001010.10000010
Subnet Mask:    255.255.255.192 = 11111111.11111111.11111111.11000000
                                  ------------------------------------- AND
Network Addr:   192.168.10.128  = 11000000.10101000.00001010.10000000
```

- Bit ที่ Mask เป็น 1 → คัดลอกค่า bit ของ IP มาตรงๆ (Network portion คงเดิม)
- Bit ที่ Mask เป็น 0 → บังคับให้เป็น 0 เสมอ (Host portion ถูก "ปัดลง" เป็น 0 ทั้งหมด = Network Address)

### Magic Number / Block Size Method — วิธีคำนวณ Subnet เร็วโดยไม่ต้องทำ Binary AND

นี่คือเทคนิคที่วิศวกร Cisco มืออาชีพใช้จริงในการคำนวณ subnet ในไม่กี่วินาที:

**สูตร: Block Size (Magic Number) = 256 − ค่า Octet ที่น่าสนใจของ Mask**

โดย "Octet ที่น่าสนใจ" คือ octet สุดท้ายของ mask ที่ไม่ใช่ 0 หรือ 255 (จุดที่การ borrow bit เกิดขึ้น)

| Mask (Octet ที่น่าสนใจ) | คำนวณ Block Size | Block Size |
|---|---|---|
| 128 | 256 − 128 | 64 |
| 192 | 256 − 192 | 64 |
| 224 | 256 − 224 | 32 |
| 240 | 256 − 240 | 16 |
| 248 | 256 − 248 | 8 |
| 252 | 256 − 252 | 4 |
| 254 | 256 − 254 | 2 |

จากนั้น **subnet ทั้งหมดจะเรียงตัวเป็นทวีคูณของ Block Size เสมอ** เริ่มจาก 0

### Worked Example — ใช้ Magic Number หา Subnet ทั้งหมดของ Mask 255.255.255.192

```
Mask ที่น่าสนใจ = 192  →  Block Size = 256 − 192 = 64
Subnet เรียงตัว: 0, 64, 128, 192   (บวก 64 ไปทีละตัว จนครบ 256)
```

| Subnet | Network Address | Broadcast Address | Usable Host Range |
|---|---|---|---|
| Subnet 0 | 192.168.10.**0**/26 | 192.168.10.63 | .1 – .62 |
| Subnet 1 | 192.168.10.**64**/26 | 192.168.10.127 | .65 – .126 |
| Subnet 2 | 192.168.10.**128**/26 | 192.168.10.191 | .129 – .190 |
| Subnet 3 | 192.168.10.**192**/26 | 192.168.10.255 | .193 – .254 |

วิธีนี้เร็วกว่าการแปลง Binary ทุกครั้งมาก และเป็นวิธีที่ใช้ตลอด Part นี้ตั้งแต่ Step 64 เป็นต้นไป

## Step 63 — CIDR Notation ตาราง /1 ถึง /32 ฉบับสมบูรณ์

**CIDR (Classless Inter-Domain Routing)** คือการเขียน Subnet Mask แบบสั้น `/n` โดย `n`
คือจำนวน bit ที่เป็น 1 ในมาส์ก (แทนการเขียน dotted-decimal เต็มรูปแบบ) เช่น `/24` = `255.255.255.0`

### ตาราง CIDR เต็มรูปแบบ /1 – /32 (จำนวน Address รวม, Usable Host, เทียบเป็นกี่เท่าของ /24)

| Prefix | Subnet Mask | จำนวน Address รวม | เทียบเป็น /24 |
|---|---|---|---|
| /1 | 128.0.0.0 | 2,147,483,648 | 8,388,608 เท่า |
| /2 | 192.0.0.0 | 1,073,741,824 | 4,194,304 เท่า |
| /3 | 224.0.0.0 | 536,870,912 | 2,097,152 เท่า |
| /4 | 240.0.0.0 | 268,435,456 | 1,048,576 เท่า |
| /5 | 248.0.0.0 | 134,217,728 | 524,288 เท่า |
| /6 | 252.0.0.0 | 67,108,864 | 262,144 เท่า |
| /7 | 254.0.0.0 | 33,554,432 | 131,072 เท่า |
| /8 | 255.0.0.0 | 16,777,216 | 65,536 เท่า |
| /9 | 255.128.0.0 | 8,388,608 | 32,768 เท่า |
| /10 | 255.192.0.0 | 4,194,304 | 16,384 เท่า |
| /11 | 255.224.0.0 | 2,097,152 | 8,192 เท่า |
| /12 | 255.240.0.0 | 1,048,576 | 4,096 เท่า |
| /13 | 255.248.0.0 | 524,288 | 2,048 เท่า |
| /14 | 255.252.0.0 | 262,144 | 1,024 เท่า |
| /15 | 255.254.0.0 | 131,072 | 512 เท่า |
| /16 | 255.255.0.0 | 65,536 | 256 เท่า |
| /17 | 255.255.128.0 | 32,768 | 128 เท่า |
| /18 | 255.255.192.0 | 16,384 | 64 เท่า |
| /19 | 255.255.224.0 | 8,192 | 32 เท่า |
| /20 | 255.255.240.0 | 4,096 | 16 เท่า |
| /21 | 255.255.248.0 | 2,048 | 8 เท่า |
| /22 | 255.255.252.0 | 1,024 | 4 เท่า |
| /23 | 255.255.254.0 | 512 | 2 เท่า |
| **/24** | **255.255.255.0** | **256** | **= 1 เท่า (base)** |

### ตาราง CIDR เมื่อ "แตก" /24 ให้เล็กลง (/25 – /32) — จำนวน Subnet ที่ได้จาก 1 x /24

| Prefix | Subnet Mask | Bit ที่ยืม | จำนวน Subnet ต่อ /24 | Address/Subnet | Usable Host/Subnet |
|---|---|---|---|---|---|
| /25 | 255.255.255.128 | 1 | 2 | 128 | 126 |
| /26 | 255.255.255.192 | 2 | 4 | 64 | 62 |
| /27 | 255.255.255.224 | 3 | 8 | 32 | 30 |
| /28 | 255.255.255.240 | 4 | 16 | 16 | 14 |
| /29 | 255.255.255.248 | 5 | 32 | 8 | 6 |
| /30 | 255.255.255.252 | 6 | 64 | 4 | 2 |
| /31 | 255.255.255.254 | 7 | 128 | 2 | 2* |
| /32 | 255.255.255.255 | 8 | 256 | 1 | 1 (host route) |

> **/31**: ตาม RFC 3021 ใช้ทั้ง 2 address เป็น usable host ได้เลย (ไม่มี network/broadcast แยก)
> นิยมใช้กับ **WAN Point-to-Point link** เพื่อประหยัด address (เรียนละเอียดใน Part 9 Static Routing)
> **/32**: ใช้กับ Host Route หรือ Loopback interface (ตามที่ใช้ใน Part 2 Loopback0 ของทุกอุปกรณ์)

## Step 64 — Subnetting Class C: Worked Examples + แบบฝึกหัด

### Worked Example 1 — Subnet 192.168.10.0/24 ให้ได้ 4 Subnet เท่ากัน

**ขั้นที่ 1**: 4 subnet ต้องยืม bit เท่าไหร่? → 2^2 = 4 → ยืม **2 bit**
**ขั้นที่ 2**: New prefix = /24 + 2 = **/26** → Mask = 255.255.255.**192**
**ขั้นที่ 3**: Block Size = 256 − 192 = **64**

| Subnet # | Network | Broadcast | Usable Host Range | Usable Hosts |
|---|---|---|---|---|
| 1 | 192.168.10.0/26 | 192.168.10.63 | .1 – .62 | 62 |
| 2 | 192.168.10.64/26 | 192.168.10.127 | .65 – .126 | 62 |
| 3 | 192.168.10.128/26 | 192.168.10.191 | .129 – .190 | 62 |
| 4 | 192.168.10.192/26 | 192.168.10.255 | .193 – .254 | 62 |

### Worked Example 2 — Subnet 192.168.10.0/24 ให้ได้ 8 Subnet เท่ากัน

**ขั้นที่ 1**: 8 = 2^3 → ยืม **3 bit** → New prefix = **/27** → Mask = 255.255.255.**224**
**ขั้นที่ 2**: Block Size = 256 − 224 = **32**

| Subnet # | Network | Broadcast | Usable Host Range |
|---|---|---|---|
| 1 | 192.168.10.0/27 | 192.168.10.31 | .1 – .30 |
| 2 | 192.168.10.32/27 | 192.168.10.63 | .33 – .62 |
| 3 | 192.168.10.64/27 | 192.168.10.95 | .65 – .94 |
| 4 | 192.168.10.96/27 | 192.168.10.127 | .97 – .126 |
| 5 | 192.168.10.128/27 | 192.168.10.159 | .129 – .158 |
| 6 | 192.168.10.160/27 | 192.168.10.191 | .161 – .190 |
| 7 | 192.168.10.192/27 | 192.168.10.223 | .193 – .222 |
| 8 | 192.168.10.224/27 | 192.168.10.255 | .225 – .254 |

### Worked Example 3 — Subnet ตาม Host Requirement (ไม่ใช่จำนวน Subnet)

**โจทย์**: บริษัทต้องการ subnet จาก `192.168.20.0/24` จำนวน **5 subnet** โดย subnet ที่ใหญ่ที่สุด
ต้องรองรับได้ **25 host**

**ขั้นที่ 1 — เช็คข้อจำกัดด้าน Host**: 25 host ต้องการ host bit ที่เหลือมากพอให้ 2^h − 2 ≥ 25
→ h=5 ให้ 2^5−2 = 30 ≥ 25 ✅ (h=4 ให้แค่ 14 ไม่พอ) → เหลือ host bit ได้อย่างน้อย 5 bit
→ Network bit ที่ยืมได้สูงสุด = 8 − 5 = **3 bit** → prefix สูงสุดคือ **/27**

**ขั้นที่ 2 — เช็คข้อจำกัดด้านจำนวน Subnet**: 5 subnet ต้องการ 2^s ≥ 5 → s=3 ให้ 8 subnet ≥ 5 ✅

**ขั้นที่ 3 — สรุป**: ทั้งสองเงื่อนไขได้ผลตรงกันที่ยืม 3 bit → ใช้ **/27** (Mask 255.255.255.224,
Block Size 32) ได้ 8 subnet (ใช้จริง 5 subnet เผื่อขยาย 3 subnet) แต่ละ subnet รองรับ 30 usable host

| ใช้งาน | Network | Usable Range |
|---|---|---|
| Subnet A | 192.168.20.0/27 | .1 – .30 |
| Subnet B | 192.168.20.32/27 | .33 – .62 |
| Subnet C | 192.168.20.64/27 | .65 – .94 |
| Subnet D | 192.168.20.96/27 | .97 – .126 |
| Subnet E | 192.168.20.128/27 | .129 – .158 |
| *(เผื่อขยาย)* | 192.168.20.160/27 – .224/27 | — |

### แบบฝึกหัด Class C — 5 ข้อ พร้อมเฉลยละเอียด

**ข้อ 1**: Subnet `192.168.1.0/24` ให้ได้ 2 subnet เท่ากัน หา Mask, Block Size, และ Network Address ของแต่ละ subnet

**ข้อ 2**: Subnet `192.168.50.0/24` ต้องการ 16 subnet เท่ากัน หา prefix ใหม่และ usable host ต่อ subnet

**ข้อ 3**: Subnet `192.168.99.0/24` ต้องการรองรับ subnet ละไม่เกิน 6 host แต่ต้องได้จำนวน subnet มากที่สุด หา prefix ที่เหมาะสม

**ข้อ 4**: IP `192.168.5.50/28` อยู่ใน subnet ใด (network/broadcast) และเป็น subnet ลำดับที่เท่าไหร่ (นับจาก 0)

**ข้อ 5**: บริษัทมี 3 แผนก ต้องการ subnet ละ 50, 20, 10 host จาก `192.168.77.0/24` โดยใช้ Fixed-Length Subnet Mask (ทุก subnet เท่ากัน) ต้องใช้ prefix อะไร และเสียพื้นที่ (waste) ไปเท่าไหร่เทียบกับ VLSM

**เฉลย:**

1. 2 subnet = 2^1 → ยืม 1 bit → **prefix /25**, Mask = 255.255.255.**128**, Block Size = 128
   - Subnet 1: 192.168.1.**0**/25 (host .1–.126)
   - Subnet 2: 192.168.1.**128**/25 (host .129–.254)

2. 16 subnet = 2^4 → ยืม 4 bit → **prefix /28**, Mask = 255.255.255.240, Block Size = 16
   → usable host ต่อ subnet = 2^4 − 2 = **14 host**

3. รองรับ 6 host ต้องการ 2^h − 2 ≥ 6 → h=3 ให้ 6 พอดี → เหลือ host bit 3 bit → ยืมได้สูงสุด 8−3=5 bit
   → **prefix /29**, Mask = 255.255.255.248, ได้ 2^5 = **32 subnet** subnet ละ 6 usable host (มากที่สุดที่เป็นไปได้)

4. `192.168.5.50/28` → Mask 255.255.255.**240** → Block Size = 256−240 = 16
   → ทวีคูณของ 16 ที่ ≤ 50 คือ 48 → **Network = 192.168.5.48/28**, **Broadcast = 192.168.5.63**
   → Subnet ลำดับ (นับจาก 0): 0,16,32,**48**,... → 48 คือทวีคูณตัวที่ 3 → **subnet ลำดับที่ 3** (0-indexed)

5. รองรับ 50 host (subnet ใหญ่สุด) ต้องการ 2^h−2 ≥ 50 → h=6 ให้ 62 ≥ 50 ✅ → ยืมได้ 8−6=2 bit
   → **prefix /26** ทุก subnet (Fixed-Length) → ได้ 4 subnet, ทุก subnet มี 62 usable host เท่ากัน
   → subnet ที่ต้องการแค่ 20 host เสีย (waste) = 62−20 = 42 address, subnet ที่ต้องการ 10 host เสีย
   62−10 = 52 address → **รวม waste มหาศาล** นี่คือจุดอ่อนของ Fixed-Length Subnet Mask (FLSM)
   ที่ VLSM (Step 66) จะมาแก้ปัญหานี้

## Step 65 — Subnetting Class B: Worked Examples + แบบฝึกหัด

Class B (`/16` default) มี host bit เหลือ 16 bit ทำให้ borrow ได้ทั้งใน Octet ที่ 3 และ 4
ทำให้การคำนวณซับซ้อนกว่า Class C เล็กน้อย แต่ใช้ **วิธี Magic Number เดิมทุกอย่าง**

### Worked Example 1 — Subnet 172.16.0.0/16 ให้ได้ 16 Subnet เท่ากัน

**ขั้นที่ 1**: 16 = 2^4 → ยืม **4 bit** (ยืมจาก Octet ที่ 3 ทั้งหมดยังไม่พอ ต้องยืมแค่ 4 จาก 8 bit ของ Octet 3)
**ขั้นที่ 2**: New prefix = /16 + 4 = **/20** → Mask = 255.255.**240**.0
**ขั้นที่ 3**: Block Size (ที่ Octet 3) = 256 − 240 = **16**

| Subnet # | Network | Broadcast | Usable Host Range |
|---|---|---|---|
| 1 | 172.16.0.0/20 | 172.16.15.255 | 172.16.0.1 – 172.16.15.254 |
| 2 | 172.16.16.0/20 | 172.16.31.255 | 172.16.16.1 – 172.16.31.254 |
| 3 | 172.16.32.0/20 | 172.16.47.255 | 172.16.32.1 – 172.16.47.254 |
| 4 | 172.16.48.0/20 | 172.16.63.255 | 172.16.48.1 – 172.16.63.254 |
| 5 | 172.16.64.0/20 | 172.16.79.255 | 172.16.64.1 – 172.16.79.254 |
| ... | (บวก 16 เรื่อยๆ ที่ Octet 3) | ... | ... |
| 16 | 172.16.240.0/20 | 172.16.255.255 | 172.16.240.1 – 172.16.255.254 |

แต่ละ subnet มี usable host = 2^12 − 2 = **4,094 host** (เหลือ host bit ทั้ง Octet 4 + 4 bit ท้ายของ Octet 3)

### Worked Example 2 — Subnet 172.16.0.0/16 ต้องการ 100 Subnet โดย subnet ละไม่เกิน 500 Host

**ขั้นที่ 1 — เช็คด้าน Host**: 500 host ต้องการ 2^h − 2 ≥ 500 → h=9 ให้ 510 ≥ 500 ✅ (h=8 ให้แค่ 254 ไม่พอ)
→ เหลือ host bit 9 bit → ยืมได้สูงสุด = 16 − 9 = **7 bit** → prefix สูงสุด = **/23**

**ขั้นที่ 2 — เช็คด้าน Subnet**: /23 ยืม 7 bit → ได้ 2^7 = **128 subnet** ≥ 100 ที่ต้องการ ✅

**ขั้นที่ 3 — สรุป**: ใช้ **/23** Mask = 255.255.**254**.0, Block Size = 256−254 = 2 (ที่ Octet 3)

| Subnet # | Network | Broadcast |
|---|---|---|
| 1 | 172.16.0.0/23 | 172.16.1.255 |
| 2 | 172.16.2.0/23 | 172.16.3.255 |
| 3 | 172.16.4.0/23 | 172.16.5.255 |
| 4 | 172.16.6.0/23 | 172.16.7.255 |
| ... | (บวก 2 เรื่อยๆ ที่ Octet 3 จนครบ 128 subnet) | ... |

แต่ละ subnet มี usable host = 2^9 − 2 = **510 host** > requirement 500 ✅

### แบบฝึกหัด Class B — 5 ข้อ พร้อมเฉลยละเอียด

**ข้อ 1**: Subnet `172.20.0.0/16` ให้ได้ 8 subnet เท่ากัน หา prefix, mask, และ usable host ต่อ subnet

**ข้อ 2**: Subnet `172.30.0.0/16` ต้องการ subnet ละไม่เกิน 1,000 host หา prefix ที่เหมาะสมที่สุด (ประหยัดสุด) และจำนวน subnet ที่ได้ทั้งหมด

**ข้อ 3**: IP `172.16.90.50/19` อยู่ใน network address และ broadcast address อะไร

**ข้อ 4**: ต้องการแบ่ง `172.25.0.0/16` เป็น 500 subnet หา prefix ที่น้อยที่สุดที่ทำได้ และ host ที่เหลือต่อ subnet

**ข้อ 5**: IP สองตัว `172.16.100.10/22` และ `172.16.103.200/22` อยู่ใน subnet เดียวกันหรือไม่? แสดงวิธีคำนวณ

**เฉลย:**

1. 8 = 2^3 → ยืม 3 bit → **prefix /19**, Mask = 255.255.**224**.0
   → usable host = 2^13 − 2 = **8,190 host** ต่อ subnet

2. 1,000 host ต้องการ 2^h−2 ≥ 1000 → h=10 ให้ 1022 ≥ 1000 ✅ (h=9 ให้แค่ 510 ไม่พอ)
   → เหลือ host bit 10 bit → ยืมได้ 16−10 = 6 bit → **prefix /22**
   → จำนวน subnet ทั้งหมด = 2^6 = **64 subnet**, usable host ต่อ subnet = 1,022 host

3. Mask /19 = 255.255.**224**.0 → Block Size (Octet 3) = 256−224 = 32
   → ทวีคูณของ 32 ที่ ≤ 90 คือ 64 → **Network = 172.16.64.0/19**, **Broadcast = 172.16.95.255**

4. 500 subnet ต้องการ 2^s ≥ 500 → s=9 ให้ 512 ≥ 500 ✅ (s=8 ให้แค่ 256 ไม่พอ)
   → ยืม 9 bit → **prefix /25** (16+9)
   → host bit ที่เหลือ = 32−25 = 7 → usable host = 2^7 − 2 = **126 host ต่อ subnet**

5. Mask /22 = 255.255.**252**.0 → Block Size = 256−252 = 4
   → `172.16.100.10` → ทวีคูณของ 4 ที่ ≤ 100 คือ **100** → network 172.16.100.0/22 (ครอบคลุม .100–.103)
   → `172.16.103.200` → 103 อยู่ในช่วง 100–103 เดียวกัน → network เดียวกันคือ **172.16.100.0/22**
   → **สรุป: อยู่ subnet เดียวกัน** ✅ (ทั้งคู่อยู่ในช่วง Octet 3 = 100–103)

## Step 66 — VLSM (Variable Length Subnet Masking)

### ทำไมต้องใช้ VLSM

จาก Step 64 ข้อ 5 เราเห็นแล้วว่า **FLSM (Fixed-Length Subnet Mask)** — ใช้ prefix เดียวกันทุก subnet
— ทำให้เสีย (waste) IP Address จำนวนมากเมื่อแต่ละ segment ต้องการจำนวน host ต่างกันมาก
(เช่น LAN ต้องการ 100 host แต่ WAN link ต้องการแค่ 2 host)

**VLSM** คือการ **"ยืม bit ซ้อนกันหลายชั้น"** โดยให้ prefix ต่างกันตามความต้องการ host จริงของแต่ละ
segment — segment ที่ต้องการ host มากใช้ prefix เล็ก (สั้น) segment ที่ต้องการ host น้อยใช้ prefix
ใหญ่ (ยาว) ทำให้ **ไม่เสีย address เกินความจำเป็น**

**หลักการ VLSM ที่ต้องจำ**: **จัดสรร (allocate) จากตัวที่ต้องการ host มากที่สุดไปน้อยที่สุดเสมอ**
(Largest-to-Smallest) เพื่อไม่ให้เกิดปัญหา subnet ทับกัน (overlap)

### Worked Example — VLSM ให้กับ VLAN ของ Enterprise Lab Topology จาก Supernet 10.10.0.0/16

จาก Lab Topology หลัก (Part 1) มี VLAN 10 (SALES), 20 (VOICE), 30 (SERVERS), 40 (WIFI), 99 (MGMT)
และ WAN Point-to-Point link 4 เส้น (ระหว่าง CORE-SW1/CORE-SW2 ไป WAN-EDGE-1/WAN-EDGE-2 และ Backup link)
สมมติความต้องการ host จริงดังนี้ (ตัวเลขจำลองสำหรับฝึก VLSM):

| Segment | Host ที่ต้องการ | คำนวณ Prefix | Prefix ที่ต้องใช้ | Usable Host |
|---|---|---|---|---|
| VLAN10-SALES | 100 | 2^7−2=126 ≥ 100 | **/25** | 126 |
| VLAN20-VOICE | 50 | 2^6−2=62 ≥ 50 | **/26** | 62 |
| VLAN40-WIFI | 60 | 2^6−2=62 ≥ 60 | **/26** | 62 |
| VLAN30-SERVERS | 20 | 2^5−2=30 ≥ 20 | **/27** | 30 |
| VLAN99-MGMT | 10 | 2^4−2=14 ≥ 10 | **/28** | 14 |
| WAN1–WAN4 (x4 link) | 2 (point-to-point) | 2^2−2=2 ≥ 2 | **/30** | 2 |

**ขั้นตอนจัดสรร (เรียงจากใหญ่ไปเล็ก) จาก Supernet `10.10.0.0/16`:**

| ลำดับ | Segment | Network ที่ได้ | Broadcast | Usable Range |
|---|---|---|---|---|
| 1 | VLAN10-SALES /25 | 10.10.0.**0**/25 | 10.10.0.127 | .1 – .126 |
| 2 | VLAN20-VOICE /26 | 10.10.0.**128**/26 | 10.10.0.191 | .129 – .190 |
| 3 | VLAN40-WIFI /26 | 10.10.0.**192**/26 | 10.10.0.255 | .193 – .254 |
| 4 | VLAN30-SERVERS /27 | 10.10.1.**0**/27 | 10.10.1.31 | .1 – .30 |
| 5 | VLAN99-MGMT /28 | 10.10.1.**32**/28 | 10.10.1.47 | .33 – .46 |
| 6 | WAN1 /30 | 10.10.1.**48**/30 | 10.10.1.51 | .49 – .50 |
| 7 | WAN2 /30 | 10.10.1.**52**/30 | 10.10.1.55 | .53 – .54 |
| 8 | WAN3 /30 | 10.10.1.**56**/30 | 10.10.1.59 | .57 – .58 |
| 9 | WAN4 /30 | 10.10.1.**60**/30 | 10.10.1.63 | .61 – .62 |

**สรุปพื้นที่ที่ใช้จริง**: ทั้ง 9 segment รวมกันใช้เพียง `10.10.0.0/24` + `10.10.1.0/26` = **320
address เท่านั้น** จาก `10.10.0.0/16` (65,536 address) — เหลือพื้นที่อีกมหาศาล (`10.10.1.64/26`
เป็นต้นไปจนถึง `10.10.255.255`) สำหรับขยายในอนาคต (VLAN ใหม่, Site ใหม่, DC ใหม่)

**เทียบกับ FLSM**: ถ้าใช้ Fixed-Length แบบเดิมที่ให้ทุก segment เป็น `/24` (256 address) ทั้ง 9
segment จะใช้ไป 9 × 256 = **2,304 address** — VLSM ในตัวอย่างนี้ประหยัดไปถึง **~86%**
นี่คือเหตุผลที่ VLSM เป็นมาตรฐานการออกแบบ Enterprise Network ทุกที่ในปัจจุบัน (เรียนการ config
จริงบน Router ด้วย static route/OSPF ใน Part 9 และ Part 11)

## Step 67 — Wildcard Mask

### Wildcard Mask คืออะไร ต่างจาก Subnet Mask อย่างไร

**Wildcard Mask** คือค่า **ตรงข้าม (Inverse)** ของ Subnet Mask แบบ bit-by-bit
- Subnet Mask: bit **1** = ต้องตรงกัน (match), bit **0** = ไม่สนใจ
- Wildcard Mask: bit **0** = ต้องตรงกัน (match), bit **1** = ไม่สนใจ (don't care)

**สูตรแปลง**: `Wildcard = 255.255.255.255 − Subnet Mask` (แต่ละ Octet แยกกัน)

ใช้กับ 2 ที่หลักในหลักสูตรนี้: **Access Control List (ACL)** และ **OSPF `network` statement**
(ทั้งสองเรื่องเรียนละเอียดใน Part 14 และ Part 11 ตามลำดับ)

### ตาราง Worked Example การแปลง Mask ↔ Wildcard

| Prefix | Subnet Mask | Wildcard Mask (255.255.255.255 − Mask) |
|---|---|---|
| /24 | 255.255.255.0 | 0.0.0.**255** |
| /26 | 255.255.255.192 | 0.0.0.**63** |
| /27 | 255.255.255.224 | 0.0.0.**31** |
| /23 | 255.255.254.0 | 0.0.**1**.255 |
| /20 | 255.255.240.0 | 0.0.**15**.255 |
| /16 | 255.255.0.0 | 0.**255**.255.255 |
| /8 | 255.0.0.0 | **0**.255.255.255 |

**Worked Example**: แปลง `/23` เป็น Wildcard
```
Mask /23        = 255.255.254.0
255.255.255.255
−  255.255.254.0
-----------------
=   0.  0.  1.255
```
→ Wildcard ของ `/23` คือ **`0.0.1.255`**

### ตัวอย่างการใช้งานจริงบน Cisco IOS

**ACL (Standard/Extended)** — ใช้ wildcard เพื่อระบุ range ของ IP ที่จะ permit/deny:
```
! อนุญาต traffic จาก subnet 192.168.10.0/24 ทั้งหมด (wildcard 0.0.0.255 = /24)
Router(config)# access-list 10 permit 192.168.10.0 0.0.0.255

! อนุญาตเฉพาะ subnet 192.168.10.0/26 (wildcard 0.0.0.63 = /26)
Router(config)# access-list 20 permit 192.168.10.0 0.0.0.63
```

**OSPF `network` statement** — ใช้ wildcard เพื่อระบุ interface ที่จะเข้าร่วม OSPF area:
```
Router(config)# router ospf 1
Router(config-router)# network 10.10.10.0 0.0.0.255 area 0
Router(config-router)# network 10.10.1.48 0.0.0.3 area 0    ! /30 WAN link, wildcard 0.0.0.3
```

> **จุดที่พลาดบ่อยที่สุด**: หลายคนสับสนเอา Subnet Mask ไปใช้ตรงๆ ใน ACL/OSPF โดยไม่แปลงเป็น
> Wildcard ก่อน — จำง่ายๆ ว่า **ACL และ OSPF ใช้ Wildcard เสมอ ไม่ใช่ Subnet Mask**
> (ต่างจาก `ip address` ที่ interface ซึ่งใช้ Subnet Mask ตรงๆ)

## Step 68 — หา Network / Broadcast / First-Last Host แบบคำนวณเร็วในหัว

### วิธีคำนวณเร็ว (Fast Mental-Math Method) — ใช้ Magic Number/Block Size

**ขั้นตอน 4 ข้อ (ใช้ได้กับทุกโจทย์):**
1. หา Octet ที่น่าสนใจของ Mask (octet ที่ borrow เกิดขึ้น) → คำนวณ Block Size = 256 − ค่านั้น
2. หาทวีคูณของ Block Size ที่ **น้อยกว่าหรือเท่ากับ** ค่า Octet ที่ตรงกันของ IP → นั่นคือ **Network Address**
3. **Broadcast Address** = Network Address + Block Size − 1 (ที่ octet เดียวกัน)
4. **First Usable Host** = Network + 1, **Last Usable Host** = Broadcast − 1

### Worked Example 1 — `192.168.5.130/26`

- Mask /26 = 255.255.255.**192** → Block Size = 256−192 = 64
- ทวีคูณของ 64 ที่ ≤ 130 → 0, 64, **128** → Network = **192.168.5.128/26**
- Broadcast = 128 + 64 − 1 = **192.168.5.191**
- Usable Range = **192.168.5.129 – 192.168.5.190**

### Worked Example 2 — `172.16.77.10/20`

- Mask /20 = 255.255.**240**.0 → Block Size = 256−240 = 16 (ที่ Octet 3)
- ทวีคูณของ 16 ที่ ≤ 77 → 0,16,32,48,**64** → Network = **172.16.64.0/20**
- Broadcast = 64+16−1=79 → **172.16.79.255**
- Usable Range = **172.16.64.1 – 172.16.79.254**

### Worked Example 3 — `10.55.14.9/22`

- Mask /22 = 255.255.**252**.0 → Block Size = 256−252 = 4 (ที่ Octet 3)
- ทวีคูณของ 4 ที่ ≤ 14 → 0,4,8,**12** → Network = **10.55.12.0/22**
- Broadcast = 12+4−1=15 → **10.55.15.255**
- Usable Range = **10.55.12.1 – 10.55.15.254**

### Worked Example 4 — `192.168.100.200/28`

- Mask /28 = 255.255.255.**240** → Block Size = 256−240 = 16
- ทวีคูณของ 16 ที่ ≤ 200 → ...,176,**192** → Network = **192.168.100.192/28**
- Broadcast = 192+16−1=207 → **192.168.100.207**
- Usable Range = **192.168.100.193 – 192.168.100.206**

### Worked Example 5 — `172.20.5.66/25`

- Mask /25 = 255.255.255.**128** → Block Size = 256−128 = 128
- ทวีคูณของ 128 ที่ ≤ 66 → **0** → Network = **172.20.5.0/25**
- Broadcast = 0+128−1=127 → **172.20.5.127**
- Usable Range = **172.20.5.1 – 172.20.5.126**

> **เทคนิคฝึกให้เร็ว**: ท่องตาราง Magic Number (Step 62) ให้ขึ้นใจ แล้วฝึกทำโจทย์แบบนี้วันละ
> 10-20 ข้อ จนสามารถตอบได้ภายใน 10-15 วินาทีต่อข้อ — นี่คือมาตรฐานความเร็วที่ข้อสอบ CCNA ต้องการ
> (ข้อสอบจริงมักมีเวลาเฉลี่ยแค่ ~90 วินาทีต่อข้อ รวมข้ออื่นที่ไม่ใช่ subnetting ด้วย)

## Step 69 — Route Summarization (Supernetting) เบื้องต้น

### แนวคิด: รวมหลาย Subnet เป็น Route เดียว

**Route Summarization** (หรือ **Supernetting** — ตรงข้ามกับ Subnetting) คือการรวม subnet
ที่ติดกัน (contiguous) หลายตัวให้กลายเป็น **route เดียว** ที่มี prefix สั้นลง เพื่อลดขนาด
Routing Table และลด CPU/Memory ที่ Router ต้องใช้ประมวลผล — สำคัญมากใน Enterprise/ISP scale
(เรียนการ config บน OSPF/EIGRP/BGP จริงใน Part 12, 28, 31)

**เงื่อนไขที่จะรวมเป็น route เดียวได้**: subnet ทั้งหมดต้อง**ติดกันในเชิง binary**
(กล่าวคือ bit ส่วนที่เหลือหลัง prefix ใหม่ต้องครอบคลุมพอดี ไม่มีช่องว่างและไม่ล้น)

### Worked Example 1 — วิธีคำนวณด้วย Binary (Classic Teaching Example)

**โจทย์**: สรุป `192.168.16.0/24`, `192.168.17.0/24`, `192.168.18.0/24`, `192.168.19.0/24`
ให้เป็น route เดียว

**ขั้นที่ 1**: แปลง Octet ที่ 3 เป็น binary
```
16 = 00010000
17 = 00010001
18 = 00010010
19 = 00010011
```
**ขั้นที่ 2**: หา bit ที่เหมือนกันทั้ง 4 ตัว (นับจากซ้าย) → `000100` เหมือนกันหมด 6 bit แรก
(2 bit ท้ายต่างกัน = 00,01,10,11 ครบทั้ง 4 ค่า พอดี = 4 subnet เต็มบล็อก)

**ขั้นที่ 3**: จำนวน bit ที่เหมือนกัน = 6 bit ใน Octet 3 + 16 bit ของ Octet 1-2 = **22 bit**
→ **Summary Route = `192.168.16.0/22`**

**ตรวจสอบ**: /22 → Block Size (Octet 3) = 256−252 = 4 → ครอบคลุม 16,17,18,19 พอดี (16+4−1=19) ✅
→ Summary Route `192.168.16.0/22` ครอบคลุม `192.168.16.0` ถึง `192.168.19.255` พอดีเป๊ะ ไม่มีส่วนเกิน

### Worked Example 2 — สรุป VLSM ของ Enterprise Lab (ต่อจาก Step 66)

จาก Step 66 เราจัดสรร VLSM ให้ VLAN10/20/30/40/99 และ WAN 4 เส้น ไปแล้ว โดยทั้งหมดอยู่ภายใน
`10.10.0.0/24` และ `10.10.1.0/26` เท่านั้น — เมื่อ DIST-SW ต้องประกาศ route เหล่านี้ไปให้ CORE-SW
(ผ่าน OSPF ใน Part 11) เราสามารถ **สรุปทั้ง 9 subnet ให้เหลือ Route เดียว** แทนที่จะประกาศ
9 route แยกกัน:

```
10.10.0.0/25    (VLAN10)  ┐
10.10.0.128/26  (VLAN20)  │
10.10.0.192/26  (VLAN40)  ├─  รวมทั้งหมดอยู่ภายใน  10.10.0.0/23
10.10.1.0/27    (VLAN30)  │   (ครอบคลุม 10.10.0.0 – 10.10.1.255 = 512 address)
10.10.1.32/28   (VLAN99)  │
10.10.1.48/30 ×4 (WAN)    ┘
```

**Summary Route ที่ DIST-SW ประกาศไปยัง CORE-SW**: **`10.10.0.0/23`**

ข้อดี: CORE-SW เห็นแค่ 1 route แทน 9 route — ถ้ามีลิงก์ใด subnet ย่อยหนึ่งเส้น flap (up/down)
บ่อยๆ ผลกระทบจะไม่ไปสั่นสะเทือน routing table ของ CORE-SW เลย เพราะ Summary Route ยังคงเดิม
ตราบใดที่ยังมีอย่างน้อย 1 subnet ย่อยที่ยัง active — นี่คือประโยชน์ด้าน **Stability** ที่สำคัญ
ไม่แพ้ประโยชน์ด้านขนาด Routing Table

> **ข้อควรระวัง**: ถ้า subnet ไม่ติดกันสนิทในเชิง binary (มีช่องว่างหรือไม่ครบบล็อก) จะไม่สามารถ
> สรุปเป็น route เดียวได้อย่างสมบูรณ์ — ต้องแตกเป็นหลาย summary route (ดูตัวอย่างจริงใน
> Step 70 ข้อ 10 ซึ่งเป็นกรณีคลาสสิกที่ข้อสอบ CCNP มักถาม)

### เฉลยละเอียดทั้ง 10 ข้อ

**ข้อ 1**: 6 subnet ต้องการ 2^s ≥ 6 → s=3 ให้ 8 subnet ✅ → ยืม 3 bit → **prefix /27**
Mask = 255.255.255.224, Block Size = 32

| Subnet | Network | Broadcast |
|---|---|---|
| 1 | 192.168.1.0/27 | .31 |
| 2 | 192.168.1.32/27 | .63 |
| 3 | 192.168.1.64/27 | .95 |
| 4 | 192.168.1.96/27 | .127 |
| 5 | 192.168.1.128/27 | .159 |
| 6 | 192.168.1.160/27 | .191 |
| *(เผื่อ)* | 192.168.1.192/27, .224/27 | ใช้เพิ่มได้อีก 2 subnet |

**ข้อ 2**: 1,000 host → 2^h−2 ≥ 1000 → h=10 ให้ 1,022 ✅ (h=9 ให้ 510 ไม่พอ)
→ เหลือ host bit 10 → ยืม 16−10=6 bit → **prefix /22**, จำนวน subnet = 2^6 = **64 subnet**
แต่ละ subnet มี 1,022 usable host

**ข้อ 3**: 500 subnet → 2^s ≥ 500 → s=9 ให้ 512 ✅ (s=8 ให้ 256 ไม่พอ)
→ ยืม 9 bit → **prefix /17** (8+9), host bit เหลือ 32−17=15 → usable host = 2^15−2 = **32,766 host**

**ข้อ 4**: Mask /27 = 255.255.255.**224** → Block Size = 256−224 = 32
→ ทวีคูณของ 32 ที่ ≤ 77 → 0,32,**64** → **Network = 192.168.50.64/27**, **Broadcast = 192.168.50.95**
→ ลำดับ subnet (0-indexed): 0,32,**64**→ 64 คือทวีคูณตัวที่ 2 → **subnet ลำดับที่ 2**

**ข้อ 5**: Mask /21 = 255.255.**248**.0 → Block Size = 256−248 = 8 (Octet 3)
→ ทวีคูณของ 8 ที่ ≤ 200 → 192,**200** → **Network = 172.16.200.0/21**, **Broadcast = 172.16.207.255**

**ข้อ 6**: Mask /23 = 255.255.254.0 → Wildcard = 255.255.255.255 − 255.255.254.0 = **0.0.1.255**
```
Router(config)# router ospf 1
Router(config-router)# network 192.168.4.0 0.0.1.255 area 0
```

**ข้อ 7**: เรียงจากใหญ่ไปเล็ก: LAN-A(100)>LAN-B(50)>LAN-C(20)>LAN-D(10)>WAN×3(2)
- LAN-A(100 host): 2^7−2=126≥100 → **/25** → `192.168.1.0/25` (usable .1–.126)
- LAN-B(50 host): 2^6−2=62≥50 → **/26** → `192.168.1.128/26` (usable .129–.190)
- LAN-C(20 host): 2^5−2=30≥20 → **/27** → `192.168.1.192/27` (usable .193–.222)
- LAN-D(10 host): 2^4−2=14≥10 → **/28** → `192.168.1.224/28` (usable .225–.238)
- WAN1: **/30** → `192.168.1.240/30` (usable .241–.242)
- WAN2: **/30** → `192.168.1.244/30` (usable .245–.246)
- WAN3: **/30** → `192.168.1.248/30` (usable .249–.250)
- เหลือ `192.168.1.252/30` ว่างสำหรับขยายในอนาคต

**ข้อ 8**: แปลง Octet 3 เป็น binary: 4=**00000100**, 5=00000101, 6=00000110, 7=**00000111**
→ bit ร่วมกัน 6 bit แรก `000001` (2 bit ท้ายครบ 00,01,10,11) → prefix ใหม่ = 16+6 = **/22**
→ **Summary Route = `10.1.4.0/22`** (ครอบคลุม 10.1.4.0 – 10.1.7.255 พอดี)

**ข้อ 9**: Mask /20 = 255.255.**240**.0 → Block Size = 16
→ `172.16.45.10` → ทวีคูณของ 16 ที่ ≤45 → 32,**48**? ตรวจใหม่: ทวีคูณ 16 ที่ ≤45 คือ 0,16,32 → **32**
→ Network A = `172.16.32.0/20` (ครอบคลุม 32–47)
→ `172.16.50.20` → ทวีคูณของ 16 ที่ ≤50 → 0,16,32,**48** → Network B = `172.16.48.0/20` (ครอบคลุม 48–63)
→ **Network A (172.16.32.0/20) ≠ Network B (172.16.48.0/20) → ไม่ใช่ subnet เดียวกัน** ❌
(นี่คือโจทย์หลอกคลาสสิก — 45 กับ 50 ดูใกล้กันแต่ block size 16 ทำให้แยกกันคนละ subnet)

**ข้อ 10**: แปลง Octet 3: 113=**01110001**, 114=01110010, 115=01110011, 116=**01110100**
→ 113 เป็นเลขคี่ (bit สุดท้าย=1) จับคู่กับ 112 ไม่ได้ (112 ไม่ได้อยู่ในรายการที่เราเป็นเจ้าของ)
→ **113 ต้องประกาศเดี่ยวเป็น `/24`**
→ 114–115 เป็นเลขคู่ต่อกัน (114 หาร 2 ลงตัว) → รวมเป็น `114.0/23` ได้ (ครอบคลุม 114–115 พอดี)
→ 116 เป็นเลขคู่แต่ 117 ไม่ได้อยู่ในรายการ → **116 ต้องประกาศเดี่ยวเป็น `/24`** เช่นกัน

**สรุป: ต้องใช้ 3 Summary Route (น้อยที่สุดที่เป็นไปได้)**:
```
203.0.113.0/24
203.0.114.0/23     (ครอบคลุม .114.0 – .115.255)
203.0.116.0/24
```

> **บทเรียนสำคัญจากข้อ 10**: การสรุป route ไม่ใช่แค่ "ดูว่าเลขติดกันไหม" แต่ต้องเช็ค
> **binary boundary alignment** เสมอ — subnet ที่จะรวมเป็น `/n` ได้ต้องเริ่มที่ทวีคูณของ Block Size
> ของ `/n` นั้นพอดี ไม่ใช่แค่เรียงเลขติดกันในเลขฐาน 10 — นี่คือจุดที่ข้อสอบ CCNP ENARSI/ENCOR
> (เรื่อง Route Redistribution & Summarization ใน Part 31) มักออกโจทย์แบบนี้

2. IP `192.168.30.100/26` อยู่ใน Network Address และ Broadcast Address อะไร?
3. VLSM ต่างจาก FLSM (Fixed-Length Subnet Mask) อย่างไร และทำไม VLSM จึงประหยัด Address มากกว่า?
4. Wildcard Mask ของ `/25` คืออะไร และใช้กับ Cisco IOS command อะไรได้บ้าง?
5. Subnet `10.1.4.0/24` ถึง `10.1.7.0/24` (4 subnet ติดกัน) สามารถสรุปเป็น Route เดียวที่ prefix อะไร?

**เฉลย:**
1. Block Size = 256−224 = **32** → prefix = **/27** (ยืม 3 bit จาก host part)
2. Mask /26 = 255.255.255.192 → Block Size 64 → ทวีคูณของ 64 ที่ ≤100 คือ **64** →
   Network = **192.168.30.64/26**, Broadcast = **192.168.30.127**
3. FLSM ใช้ prefix เดียวกันทุก subnet ทำให้ segment ที่ต้องการ host น้อยเสีย address ไปมาก
   VLSM ใช้ prefix ต่างกันตามความต้องการจริงของแต่ละ segment (จัดสรรจากใหญ่ไปเล็ก) จึงประหยัด
   address ได้มากกว่ามาก (ตัวอย่าง Step 66 ประหยัดได้ถึง ~86%)
4. `/25` → Mask 255.255.255.128 → Wildcard = **0.0.0.127** ใช้กับ **ACL** (`access-list ... permit
   <network> <wildcard>`) และ **OSPF `network` statement** (`network <network> <wildcard> area <n>`)
5. bit ร่วมกันของ Octet 3 (4,5,6,7 = 00000100–00000111) คือ 6 bit แรก → prefix = 16+6 = **/22**
   → Summary Route = **`10.1.4.0/22`**
